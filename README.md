# جرعتي — Medication Dose Tracker

مشروع Android Studio كامل (Kotlin) بيطبّق المواصفات اللي طلبتها بالكامل.

## فتح المشروع
1. افتح Android Studio (نسخة حديثة، AGP 8.5 / Gradle 8.7).
2. File → Open → اختار فولدر `medtracker`.
3. سيب Android Studio يعمل Gradle Sync (هيحمّل التبعيات من `google()`/`mavenCentral()`، فلازم يكون فيه إنترنت عادي وقتها).
4. Run على جهاز حقيقي أو إيميوليتور بـ API 26+ (أندرويد 8.0+).

هذا الـ sandbox نفسه معندوش Android SDK ولا اتصال بـ `dl.google.com`، فمقدرتش أعمل build فعلي هنا — الكود اتكتب واتراجع سطر بسطر يدويًا، بس أول build حقيقي هيحصل عندك في Android Studio.

## قرارات فنية اتخذتها (ومبررها)
- **Foreground Service من نوع `specialUse` مش `dataSync`**: `dataSync` مخصص لمزامنة بيانات فعلية، ومن أندرويد 15 بقى له حد أقصى تنفيذ ~6 ساعات/يوم إلا لو مستوفي شروط معيّنة، وممكن يترفض في مراجعة Google Play لو الاستخدام مش مطابق. `specialUse` هو المخصص لحالات زي دي مع سبب موضّح في الكود.
- **قناة الإشعار Importance = LOW لا HIGH**: من أندرويد 8+ القناة هي اللي بتحكم في السلوك الفعلي (الأولوية على مستوى الإشعار نفسه بتتجاهل). LOW يخلي الإشعار ثابت وغير قابل للمسح (`setOngoing`) من غير صوت/اهتزاز مع كل تحديث كل 15 دقيقة.
- **إشعارات مجمّعة (Grouped) بدل إشعار واحد بكل الأزرار**: كل دواء "ظهور دائم" ليه إشعاره الخاص بزرار "تسجيل" واحد، وكلهم تحت مجموعة واحدة + إشعار summary — بكده مفيش حد أقصى 3 أزرار في إشعار واحد بيقيّد عدد الأدوية.
- **عدم استخدام PNG للأيقونات**: الأيقونة التكيفية (adaptive icon) والأيقونات الداخلية كلها Vector Drawables، وده يشتغل من غير مشاكل لأن الحد الأدنى للنسخة (minSdk) هو 26.
- **`lastDoseTime` بيُعاد حسابه دايمًا من MAX(timestamp) في السجل** بعد أي تعديل/حذف — مش بس بياخد وقت آخر عملية تسجيل — عشان لو عدّلت تسجيل قديم (مش الأحدث)، الوقت المعروض في الكارت والإشعار يفضل صحيح.

## قيود حقيقية من النظام نفسه (معرفتها الأمانة الفنية)
- **مفيش ضمان 100%** إن الخدمة "مستحيل" تُقفل. على شرائح زي شيومي/أوبو/تكنو المنتشرة في مصر، الـ battery manager بتاع الشركة المصنّعة ممكن يقفل أي Foreground Service رغم كل الإجراءات دي، والحل الوحيد الحقيقي هو المستخدم يستثني التطبيق يدويًا من "توفير البطارية" ومن قوائم "Autostart / Protected apps" الخاصة بالشركة المصنّعة — التطبيق بيطلب استثناء توفير البطارية القياسي بس مش قادر يتخطى قوائم الشركات المصنّعة دي برمجيًا.
- من أندرويد 12+، تشغيل Foreground Service من سياق خلفية بحت (مثل WorkManager بعد ما النظام يقفل العملية تمامًا) ممكن يترفض من النظام نفسه (`ForegroundServiceStartNotAllowedException`) — الكود بيتعامل مع الحالة دي بهدوء (retry في الدورة الجاية) لكن مفيش حل برمجي يضمنها 100%.
- التطبيق مبني بالعربي بالكامل (`supportsRtl`, locale config) لإنك بتستخدم العربي المصري في كل حاجة.

## ميزة "قياس السكر بالكاميرا"
بتضيفها من نفس شاشة "إضافة دواء" — لما تحط علامة على checkbox "قياس بالكاميرا"، الدواء ده بيبقى نوعه مختلف: زرار "تسجيل" بيتحول لـ "تصوير" (بأيقونة كاميرا) وبيفتح كاميرا الموبايل الأساسية (مش كاميرا مبنية جوه التطبيق) — ده قرار متعمد: كاميرا الموبايل الجاهزة فيها فوكus وفلاش أحسن بكتير لقراءة شاشة جهاز قياس السكر الصغيرة من أي كاميرا مبنية يدويًا.

بعد التصوير، الـ OCR (ML Kit، شغال على الجهاز نفسه من غير إنترنت بعد أول تحميل للموديل) بيحاول يقرأ الرقم ويحطه في خانة قابلة للتعديل — **وانت لازم تأكد/تعدّل الرقم قبل الحفظ**، مفيش حفظ أوتوماتيك من غير مراجعة، لأن قراءة الأرقام السبع-قطاعات غلط وارد وده رقم طبي حساس.

**بخصوص "تصدير Excel"**: اللي بيتصدّر هو ملف **CSV** (بترميز UTF-8 + BOM) مش ملف `.xlsx` حقيقي. ده مش نقص — ملف CSV بيتفتح في Excel وGoogle Sheets وNumbers من غير أي مشكلة والعربي بيظهر صح، وعمل مكتبة حقيقية لـ `.xlsx` جوه تطبيق أندرويد كان هيضيف حجم وتعقيد وخطر تلف الملف من غير أي فايدة حقيقية إضافية. تصدير PDF حقيقي فعلاً (`.pdf` بجدول منسق) عن طريق مكتبة أندرويد المدمجة، من غير أي مكتبة خارجية.

## عايز APK فعلي — إزاي؟
الـ sandbox بتاعي معندوش Android SDK ولا اتصال بسيرفرات جوجل، فمقدرش أعمل build فعلي وأديك ملف `.apk` جاهز من هنا. عندك طريقتين، الاتنين مجانيين:

**1) Android Studio (الأسهل لو هتعدّل حاجة تاني):**
افتح المشروع في Android Studio → Run ▶ على موبايلك أو إيميوليتور. أول مرة هياخد وقت أطول عشان يحمّل الـ SDK والتبعيات.

**2) GitHub Actions (تاخد APK جاهز من غير Android Studio خالص):**
المشروع فيه ملف `.github/workflows/build-apk.yml` جاهز. لو رفعت الفولدر ده على GitHub (repo مجاني)، هيبني الـ APK أوتوماتيك على سيرفرات GitHub نفسها، وهتلاقي `medtracker-debug-apk` جاهز للتنزيل من تبويب **Actions** بعد أول push بحوالي 3-5 دقايق.
